# Automatic ecological-region detection: design (DRAFT, NOT ACTIVE)

**Status: DRAFT for owner review. No location code exists or may be written, enabled or shipped until the product decision in
`product-decision-location-detection.md` is approved.** All of this ships behind a flag that defaults OFF.

## 1. The experience
1. **Explain first.** A short, friendly screen says why: "Plantdex can find your ecological region so quests and plant lists fit where you
   are." Buttons: **Find my region**, **Choose manually**, **Not now**. Nothing is requested yet.
2. **Ask only after a tap.** "Find my region" calls the browser or native permission prompt (a user gesture is required on iOS Safari).
3. **Locate once, locally.** One low-accuracy, one-shot position read. The coordinate is rounded to the lookup's resolution the instant it
   arrives, used to resolve a region from a static asset on the device, then discarded.
4. **Show the result.** "We think you are in **Southeast Piedmont & Inland Plains**." Buttons: **Looks right**, **Change**, and **Add another
   region**. Near a boundary: "You are close to **Gulf & Atlantic Coastal Plains**. Add it too?"
5. **Manual path always available.** "Choose manually" (the ten-region list with plain descriptions), also reachable later from the region
   chip on Quests and from settings. A secondary helper, "Not sure? Pick your state and we'll suggest regions", needs no location at all.
6. **Declined or unavailable.** Denied, dismissed, timed out, insecure context, no hardware: fall back to manual, say so once in plain words,
   and **never re-prompt**. A later attempt is only ever a user-initiated button ("Find my region").

## 2. States the interface must handle
`not-asked`, `explaining`, `prompting` (system dialog open), `locating`, `resolved-confident`, `resolved-near-boundary`, `outside-coverage`
(no region yet), `denied`, `unavailable`, `timed-out`, `insecure-context`, `manual`. Each has copy, a focus target, a screen-reader
announcement and a reduced-motion rendering.

## 3. Privacy rules (the requirements, made structural)
- **Permission only.** No request without the user choosing "Find my region". Nothing on first paint, never on scan, never to use the core app.
- **Minimum precision.** One-shot, `enableHighAccuracy: false`, short `maximumAge`; coarsened to the grid cell in memory immediately.
- **Derived locally, discarded.** The lookup is a static asset downloaded like any other; **no network request carries a coordinate.** No
  third-party geocoder, no IP lookup, no timezone guess.
- **Stored: region ids only**, plus the ask state (`never | declined | granted`). Not coordinates, accuracy, or a timestamp finer than a day.
- **Not public.** Region ids are not published on any profile, board or standings function. The Field Board's published columns are unchanged.
- **Not evidence.** Location is never used for competitive verification, sighting provenance, or as proof a plant was found. Structural
  guards: the detection module imports no store, reducer, leaderboard, sightings or scan module; a test fails if any of them import it;
  `prepareImage` keeps "no path returns original bytes" and EXIF is still stripped.
- **Analytics.** `track()` still takes only an event name. Allowed events carry no region and no coordinate (for example `region_find_tapped`,
  `region_find_declined`); each must be added as a Plausible goal and mentioned on `/privacy`.
- **Accessible and optional.** Core features, scanning included, work with location off.
- **Disclosed first.** `/privacy` currently says "Plantdex does not use your device's location. It never requests location permission, and it
  stores no coordinates" (and a "No location" row). Those sentences become false the day this ships, so the policy change is a gated part of
  the decision, drafted in the decision record and applied only with the owner's approval (`legal.test.ts` guards this kind of drift).

## 4. Mapping a coordinate to a region
Pending the boundary research (branch `coord/region-boundaries-research`): primary candidates are EPA/CEC Omernik Level III ecoregions
mapped to the ten regions by a reviewed table, **not state borders**. Preferred runtime form: a small precomputed grid (a few hundred KB at
most) generated by a deterministic script, with a **boundary-uncertainty rule** (primary region plus neighbours within a stated distance and
a confidence flag). The research must report asset size, accuracy against the full polygons, and the share of land near boundaries before a
resolution is chosen. The generated grid is byte-identical across machines (repository rule for generated files).

## 6. Test plan (before anything is enabled)
Permission granted, denied, dismissed, revoked later, unavailable, timeout, insecure context, signed out, shared device with two accounts
(scope isolation, as with the existing region store); coordinates near a boundary, on a coast, in Alaska, Hawaii and offshore; fresh install
with the flag off produces no `getCurrentPosition` in the shipped bundle; no coordinate in any network request, storage key, log line or
analytics call; reduced motion; 320px width, 44px touch targets, 4.5:1 text contrast, screen-reader announcements for loading and result.

## 7. What stays out
Continuous or background tracking; a precise location of any kind; reverse geocoding services; IP-derived location; using location to rank,
verify, gate or reward anything; any server-side copy of a coordinate.
