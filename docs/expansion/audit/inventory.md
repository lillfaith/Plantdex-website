# Expansion cards #57-141: master inventory

Generated by `scripts/expansion-audit/build_inventory.py` + `write_report.py` from `origin/claude/plantdex-v0-3-supabase-verify-iic8pz` @ `26e9deafe5`. READ-ONLY audit: nothing was imported, promoted or altered; no image is committed. The machine-readable inventory is `inventory.csv` (one row per card, 73 columns).

## Method

* Branch contents were read with `git archive` into a temp directory outside the repo and never checked out. Related branches (`claude/botanical-catalog-stage-1`, `prep-expansion`, `exp`, `claude/production-system-v1`, `backup/*`) were searched by **file path only** for the species slug; counts are in the CSV column `paths_naming_species_on_other_branches`.
* Statuses are exactly: PRESENT, APPROVED, MISSING, NEEDS REVIEW, BLOCKED, NOT YET LOCATED. **APPROVED** is used only where a commit message or file in the branch records owner approval, and the quote is in the row (`owner_approval_quote`, `sprite_approval_quote`). Everything else that exists is PRESENT. NEEDS REVIEW = present but the record itself says review is pending (or a check failed). BLOCKED = cannot move forward until something else happens.
* Each card's `approved_final/provenance.json` per-file sha256 was recomputed against the files in the tree. The seven `source.files` hashes in `expansion-cards.json` were recomputed against `expansion/source/`.
* "Back-field content" is taken from each card's `profile-draft.json` (record **plus** owner text-overrides, as rendered); where it differs from `expansion-cards.json` the differing fields are listed and each diff is checked to be explained by an entry in `expansion/text-overrides.json`.
* Nothing botanical was inferred. A field the data does not contain is MISSING, not guessed.

## Findings

1. **Safety review is pending on every card (85/85).** Every caution is marked "SHORT CARD COPY — final botanical/safety review pending"; the source package itself says do not publish. 25 cards carry only a generic or family-level line ('Identify positively…' or 'Daisy-family allergy possible.'): 59, 62, 64, 66, 72, 78-79, 83, 91, 94, 96, 103-104, 109, 111, 117, 120, 123, 126, 131-134, 137, 141. All 85 are therefore BLOCKED for promotion regardless of artwork.
2. **Citations are thin.** Only 21 links across 7 cards are recorded as real direct references (`isCitation: true`, still marked "claim matching still needed"); 234 are literature **search links** (`isCitation: false`). 59 cards have no direct citation and no carried-over URL at all. Carried-over URLs (24 cards) are, per the record's own note, supporting only their documented subject, not the whole card. The package cites `PlantDex_Usable_Parts_Guide_57-142.pdf` as primary guide for usable parts; **that PDF is not in any branch (NOT YET LOCATED)**.
3. **Six cards have no main botanical image file:** #97-101, 129. #97-101 were delivered as "enlarged fronts" with no cutouts (commit 419ae2e); #129 has no main cutout in `approved_final` (reason not recorded). Their fronts exist but the cutout cannot be reused.
4. **Standalone tall/preview images exist for only 12 cards** (the ten with `expansion/assets/` folders, plus #105 and #106 via `tall_cutout_used.png`, which the commits say were rebuilt from hi-res tall cutouts); for the other 73 the preview exists only baked into `back.png`/`back_final.png`.
5. **Pixel icons: all 85 present, all within 21-24px square** (`pixel_icon_dim` column). Only #57-61 record explicit owner approval of icons ("ChatGPT handoff, owner-approved #57-61"). The icon palette/gradient checks are warnings only in `asset-spec.json`; the #57-61 icons carry 100+ colours (recorded in `assets.json` warnings).
6. **Garden sprites exist for 5 cards (#57-61) only**, with 3 growth stages each (`expansion/sprites/_build`), 80 missing. Approval is recorded only in the commit message of f3861d1 ("record owner approval of the five sprites"); **a later commit (ec7d7c1, a card-back render) overwrote the approval text in all five `sprite-brief.json` files back to "BRIEF ONLY - no sprite has been authored"**, so the file contradicts the commit. The other 80 cards have no `sprite-brief.json` either.
7. **Approval evidence is sparse.** APPROVED assembled-card status for 18 cards (63-75, 77-81) rests on commit subjects such as "assembled on approved finals" (V28, V10, V15 packages). #57-61 record owner approval of main/pixel/tall in `assets.json`. No file records approval of any card's safety text, botanical accuracy, regions or sources. Owner text edits (healing traits etc., `text-overrides.json`, all marked `by: owner`) are edits, not approvals.
8. **AI-derived art:** 25 cards use a main image whose filename marks it generated/reconstructed/edited (`main_generated_cutout_used`, `main_ai_reconstruction_used`, `main_cutout_edit`); #57-61 are recorded `origin: ai_generated_derivative`, `botanical_review_required: true`. Whether the remaining `main_cutout_used` files are photo cutouts is not recorded per card.
9. **Provenance gaps:** zip package for #67-71 not recorded; zip hash unavailable for #117-121 (zip no longer on disk); #57-61 have no zip at all (assets.json only). Source zips are **not in the repo for any batch** (see below). For the photograph-based cards, iNaturalist photo/licence manifests are not in the expansion tree; the other branches hold photo evidence for only a handful of species (see CSV column), so photo licensing/attribution for most main images is NOT YET LOCATED.
10. **Card-base:** art-less bases exist for 75 cards (#62-66, #72-141); missing for #57-61, 67-71. #57-61 predate the card-bases folder and #67-71 were assembled directly from supplied finals.
11. **Back text drift:** every card has owner overrides in `text-overrides.json` and `profile-draft.json` differs from `expansion-cards.json` for those fields, as designed. No diff is unexplained by an override (none unexplained). 80 cards have both `approved_final/back_final.png` (the as-supplied back) and owner overrides, so that file predates the edits; `back.png` is the re-render. The master spreadsheet/JSON was not updated to match (text-overrides says so).
12. **Regions are provisional** on all 85 ("Provisional ecology-based; confirm range before quest release"). Region codes are the draft PlantDex ten-region model. They are carried in the CSV as `regions_PROVISIONAL` only.
13. **Challenge/progression fields are internally consistent:** rarity/XP match the deck table (Common 100, Uncommon 175, Rare 300, Epic 500), stats are 1-5, season uses the app vocabulary after mapping Fall to autumn, use icons are within the allowed twelve. Distribution: rarity {'Common': 47, 'Uncommon': 23, 'Epic': 5, 'Rare': 10}, season {'summer': 45, 'spring': 23, 'autumn': 16, 'winter': 1}. Only one winter card (#97).
14. **Implementation:** nothing is in `CATALOGUE`, `herbs.json` or `public/` (by design; enforced by `expansion-cards.test.ts`). Promotion needs: safety review, a `collectionId`, web derivatives, sprite, plant-page copy, and an owner decision.
